## Source pipeline evidence

In the reference, `src/getUsers.ts` queries the GitHub Search users endpoint and incrementally writes raw candidates to `.cache/users.json`. `src/getUsersChina.ts` calls the same search helper with a China-location flag and writes `.cache/users.china.json`. `src/utils/index.ts` adds the `ACCESS_TOKEN` header when configured and requests users with more than 1,000 followers. `src/getUserInfo.ts` invokes both datasets in sequence. `src/utils/saveUsersData.ts` merges cached candidates with prior records, obtains full profiles, removes successfully processed entries from the cache, deduplicates, sorts by follower count, assigns ranks and caps results at 1,000. The regional run can reuse global profiles. `.ejscrc.json` maps templates to JSON files; `@wcj/ejs-cli` compiles them into `web/`.

## Discovery investigation (current phase)

The previous fetcher used only `followers:>1000 location:Nigeria`. It also filtered organizations before deciding whether to request another page, so a page containing few users could terminate pagination early. The prior result was 14 profiles, but the historical response's `total_count` was not saved. On the current API, the exact old query returns `total_count=14`, complete results, and 14 `User` items; a broader `followers:>=100 location:Nigeria` query returns 604. This reproduces the narrow-query explanation today while leaving the exact historical API snapshot unavailable.

`package.json` contains the TypeScript build, ranking validation, and page-generation scripts. The reference workflows included package publishing, release/tag actions, README edits, branch deployment, and automated Git pushes. Those unrelated side effects remain excluded; the target's scheduled refresh instead regenerates and deploys the site with GitHub Pages Actions.
